最初は、IMEをオフにした検証用の空のメモ帳などで、短い操作を試してください。対象アプリとUWSC#は通常権限で使用します。

記録して再生する

  1. F8で記録を開始し、対象アプリで文字入力・クリック・ドラッグを行います。
  2. F8で記録を終了し、生成されたスクリプトを編集欄で確認します。
  3. 「保存」で.uwsファイルへ保存します。
  4. 対象アプリを再生前の状態へ戻し、F7または「再生」で実行します。
  5. F9で一時停止・再開、F10で停止します。

既定のホットキー

キー操作
F7再生開始
F8記録開始・終了
F9再生の一時停止・再開
F10停止

「ホットキー設定」でF1〜F11と修飾キーの変更、無効化ができます。登録競合が表示された場合は別のキーを設定するか、ボタンで操作してください。

Ctrl+Alt+Shift+F11は緊急解除専用のため、操作ホットキーに設定できません。無効化して保存する場合も別の組合せを選んでください。保存済みの設定が競合するときはキーを保持し、操作ホットキーを登録せず警告を表示します。「ホットキー設定」を開いて訂正してください。LOCKHARDEXの実行中は、このキーで同じプロセスの対象実行を協調取消し、入力禁止の解除を要求します。終了後に未回収だけが残った場合は再回収を要求します。実物理機器での操作とOS実障害からの回復は未確認です。

記録設定

設定は記録開始時に反映されます。記録・再生中は変更できません。

設定動作
座標・省略の2設定がオフ絶対座標で記録します。再生前に対象の配置を確認してください。
余分な時間、マウス移動は記録しない待機時間とボタン非保持中の移動を省略します。通常ドラッグの経路は残します。処理待ちが必要なら設定をオフにするかSLEEPを追加します。
マウス座標を相対座標で記録する各入力時点のアクティブウインドウの外枠左上を基準にします。ACWとSTATUSの式を生成します。対象取得に失敗した入力は絶対座標になります。

Win32ボタンを高レベル記録する

高レベル記録の保存・読戻し・再生と、背景再生用記録の入力・再生は、検証用Win32ウィンドウを使ってWindows Sandboxで確認しました。物理入力による長時間運用と原版との比較は未確認です。

「高レベル記録（Win32ボタン）」をオンにすると、識別できるWin32プッシュボタンの左クリックや、クリックでオン・オフが切り替わる2状態のWin32チェックボックスをCLKITEMで記録します。チェックボックスは操作後に確認できた状態を記録します。状態を確認できなかった場合、押下と解放の位置が変わった場合、対象を識別できない場合は、通常の入力として記録します。右クリック、ドラッグ、キー入力は通常の入力として記録します。待ち時間を残す設定では、マウスボタンを離した時点をクリックの時刻として使います。既定はオフです。設定は保存され、記録開始時の値を使用します。

Win32メニューバーから直接実行できる項目も、押下と解放が同じ位置で項目を識別できれば、CLKITEMで高レベル記録します。サブメニューを開いて選ぶ操作や、同じパスを持つ項目は通常の入力として残ります。 記録後にメニュー構成が変わると、再生時に同じパスで最初に一致する項目が選ばれます。項目名や並び順を変更した場合は、再生前に対象を確認してください。

Win32ボタンを背景で再生する

  1. 「背景再生用に記録する（Win32ボタン）」をオンにします。設定は保存され、次に記録を始めるときに反映されます。オンの間は高レベル記録より優先されます。
  2. 「記録」またはF8で記録を開始し、対象アプリのWin32プッシュボタン、またはクリックでオン・オフが切り替わる2状態のWin32チェックボックスを左クリックします。
  3. 記録を終了し、編集欄のスクリプトを確認します。必要なら「保存」で.uwsファイルに保存します。
  4. 対象ウインドウを開いたまま「再生」またはF7で実行します。生成したCLKITEMは対象を前面に出さずに操作します。

再生時はウインドウとボタンの表示名で対象を探します。同じ名前のボタンが複数ある場合は、記録時の候補順も使います。対象ウインドウを閉じたり、ボタンの名前や候補順が変わったりしたときは、対象を確認してから再生してください。

チェックボックスは、クリック後に確認できたオン・オフを記録します。続けてクリックすると、状態を確認できなかった操作が省略されることがあります。チェックが切り替わってから次の操作を行い、記録終了後に編集欄の内容を確認してください。再生時にすでに指定した状態なら、その状態を維持します。 対象のチェックボックスが見つからない場合や、非表示または無効で指定した状態に切り替えられない場合は、CLKITEM が FALSE を返します。

再生を途中で停止しても、すでに切り替わったチェック状態は残ります。最初から再生する場合は、対象アプリを再生前の状態に戻してください。

ボタンを押した位置と離した位置が、ボタンのクライアント領域（ウインドウ枠などを除いた内側）にある場合に記録します。キーボード入力、ドラッグ、メニューの選択、識別できない対象への操作は省略されます。変換できない操作を省略すると、記録終了時に画面と生成スクリプトに警告が出ます。背景再生用の記録は既定でオフです。

記録後にクリップボードへコピーする

「記録後クリップボードへコピーする」をオンにすると、正常に開始した記録をF8・F10・「記録終了」・「停止」で終了したとき、生成したスクリプトをコピーします。既定はオフです。設定は保存され、記録開始時の値を使用します。

空白だけの結果、上限超過、警告付きの記録、開始や終了の失敗、停止の再試行ではコピーしません。本体を閉じる際の記録回収や、監視による停止検出も対象外です。編集欄には、取得できた記録結果を表示します。

コピーに失敗しても、新しい記録は未保存のまま編集欄に残ります。内容を保存するか、クリップボードの競合が解消してから編集欄の必要な範囲を選んでコピーしてください。自動では再試行しません。開けない段階の失敗では元の内容を変更しませんが、クリップボードを空にした後の書込み失敗では元の内容を保証できません。

一時停止と停止

再生中は「UWSC# 再生コントロール」が最前面に表示されます。本体を最小化しても、この画面のボタンから一時停止・再開と停止ができます。［×］も停止を要求します。

キーやボタンを押下中は、スクリプトのUPまで一時停止を保留します。停止要求では保持入力を解放します。同期Windows/COM処理は、処理が戻るまで停止できない場合があります。

「一時停止要求中」は、まだ処理が止まっていない状態です。「停止を要求しました」と表示された後は、FINALLYなどの後処理が終わるまで待ってください。実行が終わると再生コントロールは非表示になり、再び編集・実行できます。

実行中に本体を閉じると、まず停止を要求します。実行停止後、もう一度本体を閉じてください。再生コントロールは本体の終了時に破棄されます。STOPFORMで表示・非表示と位置を変更できます。OPTION TOPSTOPFORMで停止画面を最前面へ固定できます。OPTION NOSTOPHOTKEYは停止ホットキーだけを無効にし、停止ボタンと閉じる操作は維持します。変更した設定は、同じ実行の子THREADがすべて終了した後に復元します。

記録の失敗と復旧

記録の開始や監視に失敗した場合、編集欄の元の内容は保持されます。終了処理が完了すると、再び編集や記録を開始できます。

記録の終了待ちになった場合は、画面の「停止」または「記録終了」から停止を再試行できます。開始・停止処理中の終了要求は保留されるため、処理後にもう一度閉じてください。

記録終了時にフックがすでに解除されていた場合は、入力の欠落を知らせる警告と、それまでの記録結果を表示します。生成スクリプトにも警告を残します。再生前に内容を確認し、必要に応じて記録し直してください。

ウインドウ移動の記録、相対記録、長時間記録には未確認の条件があります。制限と困ったときも確認してください。

入力禁止フックの未回収が表示されている場合は、新しい記録を開始できません。入力フックの再回収を確認してください。記録器自身の終了待ちとは別の状態です。
