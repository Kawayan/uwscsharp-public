アプリからヘルプを開く

「ヘルプ」またはF1で、同梱ヘルプを既定のブラウザーへ開きます。再生・記録中は入力先を変えないよう利用できません。停止してから開いてください。F1の長押しでは繰り返し開きません。

ホットキー設定でF1を別の操作へ割り当てた場合は、そのグローバルホットキーが優先されます。「ヘルプ」ボタンを使ってください。

HTML・目次・検索をEXEへ同梱しているため、閲覧にNode.js・Python・サーバー・インターネット接続は不要です。検索にはブラウザーのJavaScriptが必要です。外部サイトへのリンクを選んだ場合は、そのサイトへの接続が必要になります。

初回は%LOCALAPPDATA%/UWSCSharp/Help/内容別の識別子/へ展開します。インストール先には書き込みません。キャッシュが欠けたり変更されたりした場合は、次の表示要求で同梱内容へ戻します。更新前のブラウザータブを使えるよう、古い内容のキャッシュは自動削除しません。削除する場合はヘルプのタブとアプリを閉じてから行ってください。

展開やブラウザー起動に失敗した場合は、画面のエラーを確認してください。保存先への書込み権限と、Windowsの既定ブラウザーの設定を確認してから再試行できます。スクリプト本文や実行結果は変更しません。

本体の表示とフォントを設定する

再生・記録の停止中に「本体設定」を開き、「本体を最前面に固定する」を選んで保存します。保存に成功してから本体へ反映し、次回起動時にも適用します。キャンセルや保存失敗では、元の設定と本体の状態を保持します。停止画面の最前面設定とは別に管理します。

保存先は%APPDATA%/UWSC/UWSC.INIの[SET] StayOnTopです。有効は1、無効は0で保存し、ログ設定や他のキーは残します。直接編集する場合、前後の空白を除いた値が1のときだけ有効です。01・+1・2・小数などは無効です。未設定時も無効です。

「本体設定」では、ダイアログのフォント名と文字サイズも変更できます。サイズは正の整数ptで指定します。StayOnTopと[SET] DefaultFontを一度に保存し、フォントは次のコマンドライン版とUWSC# アプリ実行からMSGBOX・INPUT・SLCTBOXと、フォント指定を省略したFUKIDASI・BALLOONへ適用します。同じUWSC# アプリの予約再生も、予約の実行開始時に設定を読みます。実行中にINIを変更しても、その実行の初期値は変わらず、次の実行から反映されます。実行内ではOPTION DEFAULTFONTの指定を優先し、次に開く対象画面へ適用します。

現在、DefaultFontは停止画面とPOPUPMENUには適用されません。停止画面は操作用の書体、POPUPMENUはWindows標準のメニュー表示を使います。ログ画面の書体は独立したLogFontで設定します。

小数・0以下・不正な名前は入力エラーになります。入力内容を直して再保存するか、キャンセルしてください。INIを直接編集した場合の不正値補正はダイアログの表示設定を参照してください。停止画面等へのフォント適用は未対応です。

本体の幅と高さは、物理ピクセルの正の整数で指定します。[SET] MainSizeへ保存し、保存後の本体と次回起動へ適用します。両欄を空にした場合は現在の寸法設定を保持し、片側だけの入力はエラーになります。

指定が小さい場合は、操作に必要な最小サイズへ表示を補正します。幅は既存画面の620表示単位以上、高さは指定値と内容に必要な高さの大きい方を使います。編集欄や予約表示を開くと内容に合わせて高さが変わります。INIには補正前の指定値を保持します。未指定・不正なINI値では既存の幅620表示単位と高さ自動を使います。

通常起動・スクリプト指定起動・関連付け起動で本体へ適用します。起動時に設定を読み込めない場合は固定を無効にして状態欄へエラーを表示します。「本体設定」での読込みに失敗した場合は編集・保存できません。保存失敗では画面のエラーを確認して再試行するか、キャンセルしてください。

「停止画面の幅」「停止画面の高さ」は[SET] StopSizeへ保存し、次のコマンドライン版とUWSC# アプリ実行と予約実行から適用します。幅と高さを両方とも正の整数の物理ピクセルで入力してください。両欄が空なら既存値を保持し、片側だけの入力は保存できません。保存失敗・キャンセルでは既存値を保持します。

停止画面は、停止や一時停止に必要な最小寸法と画面の作業領域に合わせて表示寸法を補正します。INIには指定値を保持します。未指定・不正なINI値では既定寸法を使います。コマンドライン版はSTOPFORMで明示した場合だけ表示し、UWSC# アプリは実行開始時に表示する既存の動作を維持します。別倍率の画面への移動は未確認です。

ログの件数とフォントを設定する

再生・記録の停止中に「ログ設定」を開き、最大行数・ログのフォント名・文字サイズ（pt）を指定して「保存」を押します。最大行数は1～100000の整数、文字サイズは正の有限数です。フォント名にはローカルの名前を指定します。キャンセルした場合は保存しません。

保存先は%APPDATA%/UWSC/UWSC.INIの[SET] LogLinesとLogFontです。2つの値をまとめて保存し、コメントや他の設定は残します。読込み・保存に失敗した場合は画面のエラーを確認してください。保存に失敗すると設定画面が残り、以前の設定ファイルを保持します。

変更は次の実行から反映します。最大行数は通常のコマンドライン版とUWSC# アプリのログ保存、およびUWSC# アプリの表示履歴に使います。フォントはUWSC# アプリのログ画面に使い、導入されていないフォントや表示できないサイズは既存の既定値へ戻します。スクリプト内のOPTION LOGLINESなどはその実行だけで優先され、INIへは書き戻しません。

スクリプトを読み込む

「読込」で.uwsファイルを選択します。UTF-8とCP932の読込みに対応しています。編集内容を破棄する場合は確認が表示されます。必要な内容は先に保存してください。

原版UWSCのUWS05形式を読み込むと、復元した本文が編集欄に表示されます。UTF-8 BOM付きで保存するため、変換済みのファイルを残す場合は別のパスを選んでください。

ファイルをドロップして再生する

メイン画面や編集欄へスクリプトファイルをドロップすると、読み込んですぐに再生します。複数ファイルでは、画面へ渡された順序の先頭だけを使います。今回確認したExplorerでは、つかんでドラッグを始めたファイルが先頭になりました。選択した順番や名前順を保証するものではありません。実行するファイルを確実に選ぶには、1ファイルずつ指定してください。通常のスクリプトファイルには追加の起動引数を渡しません。

再生・記録中、記録の開始・終了待ち、入力禁止フックの未回収中は受け付けません。未保存編集の確認を取り消した場合や読込みに失敗した場合は、現在の編集内容を保持します。先頭ファイルを読み込めなくても、2番目以降へ進みません。元ファイルの移動や削除は行いません。

この機能は試作段階です。Windows Sandbox内のExplorerで、単独・複数ファイルのドロップを確認しています。権限が異なるアプリ間での動作確認は未完です。フォルダーは読み込めません。

.uwsファイルを指すショートカット（.lnk）もドロップできます。対象のスクリプトを読み込み、ショートカットに設定された引数をWindowsのコマンドライン規則で分割してPARAM_STRへ渡します。空白を含む引数は二重引用符で囲んでください。"日本語 alpha" betaは2つの引数になります。""は空文字列1つです。

実行時の基準フォルダーは対象スクリプトのフォルダーです。ショートカットの「作業フォルダー」は使いません。対象が見つからない場合、.uwsファイルを対象として読み取れない場合やリンク自体の読取りに失敗した場合はエラーになります。現在の編集内容を保持し、後続のファイルへは進みません。ショートカットを重ねた構成の動作確認は未完です。

編集して実行する

「スクリプト編集・実行結果」を展開して本文を編集します。「再生」は編集中の内容を実行します。PRINTの出力は実行結果で確認できます。

INIの既定パスは選択したファイルに基づきます。未保存の場合は現在の作業フォルダーのuntitled.uwsを基準にします。

実行結果は長時間の出力によるメモリ増加を抑えるため、表示量を制限しています。長い出力の末尾や古い出力の先頭を削除する場合があります。絵文字や補助漢字のサロゲートペアを途中で分断しないように切り詰めます。原版のログ保存・表示履歴の全機能には対応していません。

ファイルへ保存する

「保存」で保存先を指定します。保存時の文字コードはUTF-8 BOM付きです。保存に失敗した場合はエラーを確認し、別の書込み可能な場所へ保存してください。

登録した項目をランチから起動する

「ランチ」から「登録を編集…」を選ぶと、起動する項目を登録できます。上位は35枠で、階層を1段階だけ作り、階層内にも35枠まで登録できます。空き位置は保存され、起動メニューには表示しません。空の階層は選択できません。

位置を選び、「起動項目を登録・編集」でタイトルと対象ファイルを指定してください。手入力の相対パスはUWSC#の配置フォルダーを基準にし、登録後は絶対パスで保存します。ファイルを移動した場合は登録し直してください。

追加引数は一覧の1項目を1つの引数として渡します。「追加」「選択を変更」「削除」「上へ」「下へ」で編集できます。空欄のまま追加すると空文字列を渡します。空白や引用符を独自に分割しません。既定アプリで開くファイルには追加引数を指定できません。

項目画面の「反映」は登録画面の下書きへ戻します。「設定を保存」でファイルとメニューを更新します。「取消」では編集前の登録を保持します。登録の編集は再生・記録の停止中だけ行えます。

スクリプトは同じ配置の関連付け用EXEで別プロセスとして再生します。EXEは直接起動し、その他のファイルはOSの既定アプリへ渡します。本体の再生・記録中も登録済み項目を起動でき、本体を閉じても起動先を停止しません。起動先のアプリが既存インスタンスを再利用する場合もあります。

対象が消失した場合や起動に失敗した場合は、ランチの通知を確認してください。登録や本体の原稿・実行結果は保持します。「設定を再読込み」に失敗した場合も、直前のメニューを保持します。設定を読めない状態では登録編集を止め、初回起動では項目を実行できません。

破損した設定を初期化する場合は「退避して初期化…」を選び、確認に同意してください。元のファイルを同じフォルダーの別名へ退避できた場合だけ空の登録へ置き換えます。保存・退避に失敗した場合は元の内容を保持します。設定は4MiB以内で保存します。

本体の「トレイに格納」で、画面を通知領域にしまえます。通知領域に格納した後も、アイコンの左クリックでランチを開けます。ダブルクリックとの区別を待って表示するため、少し間隔があります。ダブルクリックは通常画面へ戻り、右クリックは「開く」「終了」を表示します。ランチ用ホットキーでもメニューを開けます。「表示位置を設定…」で、カーソル位置または画面の物理ピクセルによる横・縦座標を指定できます。保存した位置は次のホットキー表示から適用します。ボタンと通知領域から開く位置は変わりません。

背景表示のWindows Sandboxで、診断による格納・復帰を確認しました。通知領域のアイコンを物理マウスで操作する検証は未実施です。

位置はUWSC.INIの[LUNCHMENU]にあるPositionへ保存します。両方が-1の場合だけカーソル位置を使い、0,0は画面原点を指定します。負座標も指定できますが、画面端ではメニューが収まるようUWSC# アプリが配置を補正します。取消では保存しません。読込み失敗ではメニューを開かずエラーを通知し、保存失敗では入力を保持します。

「登録を編集…」で「ランチ用ホットキー」を有効にし、Ctrl・Alt・Shift・Winの組合せと、数字・英字・F1～F24からキーを選んで「設定を保存」を押します。既定は未設定です。本体用キーとの競合や新キーの登録失敗では、以前の設定とキーを維持します。「取消」では変更しません。

保存後に旧キーを解除できなかった場合も、新設定と新キーは有効です。旧キーからはランチを開かず、本体に「回収未完了」と未回収キーを表示します。ランチの「ホットキーを再回収」で解除を試してください。未回収中は別キーへの変更を止めます。終了時にも回収を試み、解除を確認できなければ通知します。

起動時にキーを登録できなくても、有効な登録内容は編集できます。入力送信後にキーを復元できなかった場合は、実行終了後に「設定を再読込み」で再適用してください。記録では有効キーと未回収キーを制御用の操作として除外します。

実行結果のログ

PRINTの内容を、主スクリプトと同じフォルダーのUWSC.LOGへ保存します。未保存のスクリプトでは、起動時の作業フォルダーを基準にします。既定は日時付き・直近2,000件です。ログOPTIONで保存先・上限・形式を変更できます。

実行中は約1秒ごとに保存を試み、正常終了・エラー・取消の後にも最終保存します。保存失敗は画面へ通知し、コマンドライン起動ではstderrにも診断します。周期保存が失敗しても実行は止めず、設定した件数の範囲で未保存の出力を保持して再試行します。PRINT専用ログウィンドウはLOGPRINTで制御できます。表示履歴はLOGLINESで件数を変更し、合計100000 UTF-16単位でも制限します。メイン画面の実行結果は別の表示量制限です。

通常のGUI再生では、PRINTの専用ログウィンドウを自動表示します。ログウィンドウを閉じても保存は続き、次の実行では再び自動表示します。再実行時は表示履歴を消去し、ログOPTIONの保存先・件数・形式を既定値から開始します。

実行中にアプリを閉じると、まず停止を要求します。停止が完了してからもう一度閉じてください。保存していない編集内容がある場合は、破棄するかを確認します。

入力フックの未回収が表示されたとき

終了した実行の入力禁止フックが残る場合、「未回収所有者」の件数を表示し、再生・記録・ドロップ再生の開始を止めます。「入力フックを再回収」で、同じプロセスが保持する対象へ明示的に1回要求できます。実行中の入力禁止や他プロセスを解除する操作ではありません。記録器の終了待ちは、従来の停止・記録終了の操作を使ってください。

再回収中は重ねて要求できません。過去の診断は実行結果へ残し、現在の件数とは分けて表示します。0件になれば開始制限を解除します。未回収中でも、停止中の編集と保存はできます。状態を確認できない間も開始を制限します。

照会・再回収中に閉じると、完了後にもう一度閉じるよう表示します。未回収のまま閉じる確認で「いいえ」を選ぶと画面へ戻り、「はい」を選ぶと通常の未保存確認へ進みます。終了確認では「いいえ」が既定で選ばれます。プロセス終了は明示解除の成功を示しません。追加の自動再試行や、OS・所有スレッドの強制回復は行いません。

UWSC# アプリをスクリプト引数付きで起動すると、従来どおり実行後に自動終了します。未回収時も対話待機を追加せず診断を出し、元の非ゼロ終了コードを維持します。元が0の場合だけ1にします。コマンドライン版の明示的な待機はコマンドライン版での手動再回収を参照してください。

この回収機構の対象となるLOCKHARDEXは、コマンドライン版とUWSC# アプリで使用できます。公開経路の機能全体の受入は一部対応です。回収操作の接続を、入力禁止機能全体の完成や実際のOSフック解除障害の受入とは扱っていません。

スクリプトからUWSC# アプリを再起動する

POFF(P_UWSC_REEXEC) または POFF(P_UWSC_REEXEC, FALSE) は、UWSC# アプリを閉じて新しく開きます。TRUE を指定すると、保存済みのスクリプトを元の引数で再実行します。編集中の内容も再実行するには、先にファイルを保存してください。

再生後に入力を回収し、通常の終了処理が済むと新しいプロセスを起動します。未保存の変更を破棄するか確認されたら、「いいえ」で再起動を取り消せます。編集中の内容は画面に残ります。

関連付け用の実行ファイルから起動した場合も指定できます。TRUE で関連付け用の実行ファイルからスクリプトを再実行し、省略または FALSE で通常のUWSC# アプリ画面を開きます。

毎回同じ行に達すると再実行を繰り返すため、必要な場合だけ呼び出してください。予約実行では、P_UWSC_REEXEC を指定すると捕捉できるエラーになります。通常再生と予約実行で使えるWindowsの電源や画面の操作は、Windowsの電源と画面を操作するを参照してください。
