    UWSC# ヘルプ / 関数の定義

    関数の定義

    PROCEDURE・FUNCTIONで処理をまとめ、MODULE・CLASSで変数と関数をまとめられます。THREADを使うと、別の処理を並行して実行できます。

    コマンドライン版とUWSC# アプリの採用範囲です。

    PROCEDURE：戻り値のない手続き

    Greet("太郎")

PROCEDURE Greet(name)
    PRINT "こんにちは、" + name
FEND

    呼出しは関数名と丸括弧で行います。PROCEDUREの呼出し結果はEMPTYです。処理結果を値として返す場合はFUNCTIONを使用してください。

    FUNCTION・RESULT：値を返す関数

    PRINT Twice(3)

FUNCTION Twice(value)
    RESULT = value * 2
FEND

    戻り値はRESULTへ代入します。RESULT未設定での初期値はEMPTYです。EXITは現在の手続き・関数を抜けます。EXITに戻り値の式を続ける書式は採用していません。

    PRINT MakeValue()

FUNCTION MakeValue()
    HASHTBL values
    RESULT = values
    RESULT = 7
FEND

    手続き・関数内のRESULTへ再代入すると、前の値の種類にかかわらず指定した値へ置き換えます。RESULT=HASH_REMOVEALLも消去命令にはせず、数値の-109を設定します。連想配列を消去して返したい場合は、通常のHASHTBL変数へHASH_REMOVEALLを代入してからRESULTへ渡してください。通常のHASHTBL変数の消去・型制限は変わりません。

    PROCEDURE内のRESULT代入を受け付け、呼出し結果をEMPTYとするのはUWSC#の採用仕様です。原版Free 5.3.0.2では、単純なRESULT代入を含む手続きが実行前の診断となる条件を確認しています。

    返値は通過するFINALLYの後で確定し、VARの書戻しが成功してから呼出し元へ返します。FINALLYや書戻しで失敗した場合、代入先へ返値を渡しません。配列・HASHTBLの返値は独立した内容を保持し、外部objectは同じ参照を渡します。

    メイン処理は最初の関数定義より前に書いてください。関数定義の後にメインの実行文を置く形式は拒否します。名前の重複や予約名も拒否します。

    既定引数

    PRINT Multiply(5)
PRINT Multiply(5, 3)

FUNCTION Multiply(value, factor = 2)
    RESULT = value * factor
FEND

    値・VAR・配列パラメーターに既定値を指定できます。リテラル、名前、添字、単項・二項演算の式を使い、関数やCOMメンバーの呼出しは許可しません。既定値のある引数の後に必須引数は置けません。呼出し時の引数の不足・過剰はエラーになります。

    ShowTotal(, 4)

PROCEDURE ShowTotal(first = 2, second = 3)
    PRINT first + second
FEND

    カンマで引数を明示的に省略した場合も、既定値を使います。引数の個数と必須位置の省略は、どの実引数も評価する前に検査します。呼出しに失敗すると分かっている段階で、先行引数の関数や外部操作を実行しません。正常な実引数は左から右へ1回ずつ評価します。

    既定値の評価先

    PUBLIC baseValue = 3
ShowNext()
baseValue = 7
ShowNext()
ShowNext(9)

PROCEDURE ShowNext(value = baseValue, nextValue = value + 1)
    PRINT nextValue
FEND

    既定値は省略した位置だけで、左から右へ評価します。評価先は呼出し先のスコープで、現在のPUBLIC・CONST、先に設定した仮引数を参照できます。呼出し元のローカル変数は見えません。使われなかった既定値は評価せず、未定義名や型の不一致は、その値が必要になった時点でエラーになります。

    VAR引数を省略した場合は独立したローカル値を作り、既定値に指定した変数へ書き戻しません。明示したVARには、従来どおり書込み可能な変数・配列要素を指定します。配列の既定値には、呼出し先に見えるPUBLIC配列や先行する配列引数を使えます。型と次元数は指定した[]に一致する必要があり、x[]=EMPTYを省略すると配列の型エラーになります。原版とはVAR省略時や配列の既定値の動作が異なる条件があります。

    変数のスコープ

    DIMと仮引数はその実行領域のローカル変数です。通常のPUBLICはメインの直下で宣言し、複数の名前や配列を指定できます。PUBLICの再宣言とOPTPUBLICも参照してください。MODULE・CLASSの外のCONSTは、関数内で宣言してもメイン実行前に一度初期化して共有します。関数内のDIMで共有名と同名を宣言した場合は、そのローカル変数を参照します。

    PUBLIC shared = 1
ShowLocal()
PRINT shared

PROCEDURE ShowLocal()
    DIM shared = 2
    PRINT shared
FEND

    VAR引数：呼出し元へ値を書き戻す

    DIM count = 1
Increment(count)
PRINT count

PROCEDURE Increment(VAR value)
    value = value + 1
FEND

    VARの実引数には書き戻せる変数や配列要素を指定します。通常の同期呼出しでは独立した値として処理し、正常終了時に仮引数の順で書き戻します。本文の失敗・取消時は通常の書戻しを行いません。THREADで起動した処理では、VARでも書き戻しません。

    この方式は呼出し中に変数の実体を共有する参照とは異なります。同じ変数を複数回渡した場合も、途中の変更を仮引数同士で共有しません。書戻しの途中で後続が失敗した場合、先に完了した更新は巻き戻しません。書戻し先の添字や型変換でスクリプトエラーになった引数は飛ばし、残るVAR引数も処理してから先のエラーを通知します。エラー時に呼出し元の代入先へ返値を渡しません。取消やホストの障害では継続しません。

    複数のVAR書戻しでスクリプトエラーが起きたときは、仮引数の順で最初に起きたエラーだけを通知します。DLL書戻し中の添字関数を使った比較では、原版が2件目の範囲外エラーを外側のEXCEPTにも通知する場合や、添字の数値変換に失敗した後のVARが更新されない場合がありました。

    配列パラメーター

    DIM values[1] = 1, 2
Change(values)
PRINT JOIN(values, ",")

PROCEDURE Change(VAR items[])
    items[0] = 9
FEND

    配列の次元数に合わせて仮引数に[]を付けます。上の例は1次元です。VARなしの通常配列引数はコピーとして扱い、VAR付きは正常終了時に書き戻します。多次元配列・部分配列には形状や書戻し先の検査があります。

    1次元配列形式のパラメーターにはHASHTBLも渡せます。VARのない引数は独立した内容で処理し、呼出し元へ書き戻しません。明示したVAR引数だけを正常終了時に書き戻します。同じ連想配列を複数のVAR引数へ渡すと、仮引数ごとの変更は独立し、後の書戻しが優先します。外部オブジェクトは同じ参照を保持します。

    MODULE・CLASS：変数と関数をまとめる

    MODULEからENDMODULEまでに変数や関数をまとめ、名前.変数や名前.関数()で使います。CLASSからENDCLASSも同じ動作です。実行ごとに一つの共有状態を持ち、呼出しのたびに別の実体を作る構文ではありません。次の実行では新しい状態から始めます。

    PRINT Counter.total
Counter.Add(2)
PRINT Counter.total

MODULE Counter
    PUBLIC total = 0
    DIM initial = 10
    PROCEDURE Counter()
        total = initial
    FEND
    PROCEDURE Add(value)
        THIS.total = THIS.total + value
    FEND
ENDMODULE
// 出力: 10、12

    直下のPUBLICは外から読み書きできる変数、DIMは内部だけで使う非公開の変数、CONSTは読み取り専用の定数です。非公開変数を外から参照したり、定数へ代入したりすることはできません。MODULE・CLASS直下のHASHTBL宣言、定義の入れ子、継承、複数の実体を生成する形式は対象外です。

    メイン処理の前に変数を初期化します。まとまりの名前と同じ引数なしのPROCEDUREまたはFUNCTIONがあれば、初期化処理として一度呼び出します。上の例ではCounter()が初期値を10にします。この初期化処理へ引数を渡す形式は使えません。

    内部ではTHIS.totalのように現在のまとまりを明示できます。同名のローカル変数や仮引数がある場合も、THISでそのまとまりの変数を指定できます。GLOBAL.関数名(...)は外側のユーザー関数や組み込み関数の呼出しです。GLOBALで外側の変数を読み書きする形式は対象外です。

    THREAD：別の処理を並行して実行する

    THREAD 関数名(引数...)でユーザー関数・手続きを起動します。呼出し元は完了を待たず、次の文へ進みます。通常の関数呼出しと違い、戻り値を受け取りません。EVAL("THREAD Worker()")でも起動できますが、返値は空文字列であり、処理のIDではありません。

    PUBLIC done = FALSE
THREAD Worker()
FOR attempt = 1 TO 100
    IF done THEN BREAK
    SLEEP(0.01)
NEXT
PRINT done

PROCEDURE Worker()
    SLEEP(0.02)
    done = TRUE
FEND

    引数は開始時の値をコピーし、VAR引数でも呼出し元へ書き戻しません。ローカル変数は処理ごとに分かれます。PUBLICやMODULE・CLASSの変数は同じ実行の処理間で共有します。複数の処理が同じ値を更新する順序は、スクリプト側で調整してください。

    CTRLTRD：停止・再開・終了を要求する

    CTRLTRD(id, mode)で制御します。IDは同時に使える64枠の番号0～63で、最初の処理は0から空き枠を使います。終了した枠は再利用されるため、古いIDが後の別処理を指す場合があります。WindowsのThread IDとは異なります。

    modeにTRD_SUSPENDを指定すると実行の区切りで停止し、TRD_RESUMEで再開、TRD_QUITで終了を要求します。優先度はTRD_IDLE・TRD_LOWEST・TRD_LOWER・TRD_NORMAL・TRD_HIGHER・TRD_HIGHESTの6段階です。引数は2個とも必須で、返値は空文字列です。詳しくはCTRLTRDの関数リファレンスを参照してください。

    メイン処理の終了・取消・EXITEXITでは、起動した処理にも終了を要求し、後処理と終了を待ちます。取消後にFINALLYを実行するにはOPTION OPTFINALLYを指定してください。起動した処理の未捕捉エラーとEXITEXITは実行全体へ伝わり、解放失敗も通知します。

    停止は処理が区切りへ戻ったときに行います。取消を無視するWindows・COM等の外部処理を強制終了する機能ではありません。物理キーやマウスの状態はWindows全体で共通なので、複数の処理から同時に操作する順序もスクリプト側で調整してください。

    再帰と制限

    ユーザー関数の再帰呼出しに対応しています。既定の呼出し深度上限は128です。COMのVAR・名前付き引数はユーザー関数の引数と別の経路で処理します。

    DEF_DLLは宣言の構文検査と登録に対応しています。モジュール内で宣言した名前はそのモジュールに属するため、外部からはモジュール名.関数名()で参照してください。

    Windows x64のコマンドライン版とUWSC# アプリでは、値渡しのINT、LONG、BOOL、UINT、DWORD、BYTE、BOOLEAN、WORD、LONGLONG、FLOAT、DOUBLEを引数と戻り型に指定できます。戻り型を省くかVOIDにすると、スクリプトには0を返します。32ビットDLLの中継では、EXTENDEDの戻り値をx87から倍精度に変換し、VARTYPEが5の数値として返します。値渡しのEXTENDED引数は、倍精度の入力を80ビットへ変換して渡します。元の整数を保持しているLONGLONGの戻り値は、SET8087CWで指定した方向へ丸めます。COMから受け取った符号なし64ビット整数（VT_UI8）をEXTENDEDへ渡す場合も、元の整数が保持されていればSET8087CWで指定した方向へ丸めます。この丸め方向は、値渡し、単体のVAR EXTENDED、EXTENDED[]、構造体のVAR EXTENDED・EXTENDED[]フィールドで反映されます。最近接では、9007199254740993は9007199254740992になります。最大値9223372036854775807は最近接と上方向で9223372036854775808に、下方向とゼロ方向で9223372036854774784になります。最小値-9223372036854775808は倍精度で表せるため、そのまま渡ります。この丸め方向は、値渡しと単体のVAR EXTENDED、EXTENDED[]、構造体のVAR EXTENDED・EXTENDED[]フィールドに適用します。外側の引数領域では1引数につき12バイトです。64ビットDLLでEXTENDEDを使う場合は、呼出し時にエラーになります。

    32ビットDLLの中継では、構造体のEXTENDEDフィールドを通常配置では8バイト境界に揃え、PACKでは直前のフィールドの直後に配置します。フィールド自体は10バイトです。VAR EXTENDEDフィールドには10バイトの領域を指すポインターを置きます。どちらもDLLが変更した値を倍精度に変換して書き戻します。構造体のEXTENDED[]フィールドには配列の先頭を指すポインターを置きます。数値変数の扱い、書戻し、NULLの扱いは、構造体の外でEXTENDED[]を指定した場合と同じです。

    32ビットDLLの中継では、EXTENDED[]の要素を10バイト間隔で並べ、先頭へのポインターを渡します。数値を格納した変数は1要素として扱います。VARの有無にかかわらず、DLLが変更した値を倍精度に変換して書き戻します。NULLを直接指定するとヌルポインターを渡します。NULLを格納した変数を指定すると、DLLを呼び出す前にエラーになります。

    32ビットDLLの中継で単体引数をVAR EXTENDEDと宣言すると、DLLに10バイトの領域へのポインターを渡します。書き戻す値は倍精度に変換し、VARTYPEが5の数値として変数や配列要素に代入します。単体・配列・構造体フィールドのEXTENDEDの書戻しにはDLLが戻った時点の丸め方向を使います。DLLが丸め方向を変更すると、その呼出しの書戻しに反映されます。UWSC#は中継の浮動小数点状態を復元するため、丸め方向や例外マスクの変更は次のDLL呼出しに持ち越されません。DLL内のゼロ除算が浮動小数点例外になった場合、その呼出しではEXTENDEDの値を書き戻さず、実行時エラーを通知します。構造体のVAR EXTENDED、EXTENDED[]、VAR INTを同時に変更した場合も、例外が起きると3つのフィールドへの書戻しを行いません。変換結果が無限大またはNaN（非数）になると、UWSC#ではDLLから戻った後に書戻しエラーになります。原版では、単体のVAR EXTENDEDにDLLが書き込んだNaNや正負の無限大が数値として書き戻されます。UWSC#では、EXTENDED[]の要素にNaNがあると、その配列の値を保ちます。先に書き戻した別の引数や構造体フィールドの値は残り、後続の書戻しは中断します。たとえば文字列"1.5"は1.5、TRUEは1、FALSEとEMPTYは0として渡します。COMから受け取った真偽値（VT_BOOL）は、真を-1、偽を0として渡します。この変換は、EXTENDED[]の要素や、構造体のVAR EXTENDED・EXTENDED[]フィールドにも適用します。COMの通貨型（VT_CY）や十進数型（VT_DECIMAL）を単体のVAR EXTENDEDに渡すと、DLLが書いた値は数値型5として書き戻されます。通貨型の入力は、SET8087CWで指定した方向へ丸めてから80ビットへ拡張します。たとえば通貨型の最大値922337203685477.5807は、最近接と上方向で922337203685477.625、下方向とゼロ方向で922337203685477.5になります。十進数型の0.1と-0.1は、丸め方向の指定にかかわらず同じ倍精度値を80ビットへ拡張します。通貨型・十進数型の入力変換は、値渡し、単体のVAR EXTENDED、EXTENDED[]、構造体のVAR EXTENDED・EXTENDED[]フィールドに適用します。COMの単精度型（VT_R4）の0.1と-0.1は、4つの丸め方向すべてで、元の単精度値をそのまま80ビットへ拡張して渡します。単精度型の最大有限値と、最小の正の非正規値（2^-149）も、元の値を保ったまま渡ります。COMの単精度型または倍精度型がNaNまたは正負の無限大を返した場合、UWSC#はCOMの戻り値を受け取る時点で実行時エラーを通知します。原版はこれらの値をEXTENDEDの値渡し、単体のVAR EXTENDED、EXTENDED[]、構造体のVAR EXTENDED・EXTENDED[]フィールドに渡しました。書戻しのある経路では、DLLが書き込んだ有限値を数値型5として受け取りました。原版では、配列や構造体の先頭・末尾・両方にこれらの値を指定しても、DLLからの書戻しが反映されました。3要素に単精度のNaN、倍精度の正の無限大、単精度の負の無限大を配置した比較では、全6通りで原版が宣言順に値を渡し、すべての要素に書き戻しました。十進数型の9007199254740993は、丸め方向の指定にかかわらず9007199254740992として渡ります。十進数型の最大値・最小値も、4つの丸め方向すべてで正負の2^96として渡ります。十進数型の最小の非ゼロ値である正負の10^-28は、4つの丸め方向すべてで、数学的に最も近い倍精度値より絶対値が1 ULP大きい値として渡ります。この変換と数値型5への書戻しは、EXTENDED[]の要素と、構造体のVAR EXTENDED・EXTENDED[]フィールドにも適用します。空文字や数値に変換できない文字列は、DLLを呼び出す前にエラーになります。NULLの直接指定はヌルポインターを渡します。NULLを格納した変数でもDLLは呼び出され、書き戻し時にエラーになります。

    DEF_DLL MulDiv(int,int,int):long:kernel32.dll
PRINT MulDiv(3.5,1,1)

    整数引数の変換にはSET8087CWの丸め設定を使います。SET8087CWで設定したx87制御語は、32ビット中継ではDLLの関数を呼んでいる間だけ適用します。64ビットDLLを直接呼び出す場合、DLL内のx87やSSEの制御値にはSET8087CWの指定を適用しません。同一プロセスのCOMメソッドを呼ぶときや、プロパティを取得・代入するときは、呼出し中だけこの指定をx87制御語に適用します。SSEの制御値は呼出し元の設定を使います。別プロセスのCOMサーバーでは、サーバー自身の制御語を使います。イベント処理からそのサーバーを呼び直したときも同じです。同期COMイベントの処理で別の制御語を指定して同じCOMオブジェクトを呼び直すと、内側の呼出しが終わったときに外側のx87制御語が復元されます。イベント処理でSET8087CW(0)を指定して同じCOMオブジェクトを呼び直すと、内側の呼出しは最外の呼出し前のx87制御語を使います。内側の呼出しが終わると、外側のx87制御語に戻ります。同一プロセスのCOMメソッドでは、x87のゼロ除算のマスクを解除すると、メソッド内のゼロ除算をEXCEPTで捕捉できます。戻り値の代入先には呼出し前の値が残り、その後もCOMメソッドを呼び出せます。同期COMイベントの通知処理で捕捉しなかった例外をサーバーが発火元へ返した場合は、イベントを発火した呼出しを囲むEXCEPTで捕捉できます。SET8087CW(0)で設定を解除すると、中継先の既定値で呼び出します。THREADから32ビットDLLを並行して呼ぶ場合は、各スレッドの設定をその呼出しに適用します。32ビット中継では、ゼロ除算や負数の平方根による無効演算のマスクを解除すると、DLL内で発生した該当の例外をEXCEPTで捕捉できます。例外が発生した呼出しの戻り値の代入先とVAR引数には呼出し前の値が残り、その後もDLLを呼び出せます。既定の設定で上の例を実行すると、表示は4です。対応済みのスカラー戻り型に末尾の [] が付いている場合も、返る値は1つです。たとえば INT[] は INT と、STRING[] は STRING と同じ型の値を返します。配列や構造体の値を返す呼出しは未対応です。UWSC#で構造体を戻り型に指定した関数を呼ぶと、DLLを実行する前にエラーが発生します。このエラーはEXCEPTで捕捉できます。

    DLL書戻し中の添字関数が別のユーザー関数を呼ぶ場合、内側のVAR書戻しエラーは呼出し元のEXCEPTで処理できます。未処理の場合は外側のVARとDLLの残りの書戻しを終えてから通知します。内側の関数で停止を確認した場合は、FINALLYとVAR書戻し後の返値を呼出し元へ代入してから、外側の後続文を省きます。二階層の単体VARと範囲外の配列要素を比較した結果です。

    添字関数が三階層または四階層になる場合も、内側のVAR書戻しエラーは中間または外側のEXCEPTで処理できます。中間で処理して関数が正常に戻れば、外側は返値を受け取ります。OPTFINALLY付きで停止した場合は、各階層のFINALLYで更新したVAR引数を順に書き戻します。

    UWSC#では、添字関数を含む四階層の呼出しでも、内側のFINALLYで更新したVARが外側へ順に届きます。通常時に内側のVAR書戻しエラーが添字関数の外へ出ると、添字0を使って外側のDLL引数を書き戻した後に通知します。

    添字関数の本文から静的CALLを実行する場合も、CALL先のVAR書戻しエラーは、CALL先または添字関数のEXCEPTで処理できます。停止時は、CALL先で完了した代入を保持し、添字関数のCALL後の文を省略します。OPTFINALLYを指定していれば、CALL先から添字関数へ順に保留中のFINALLYを実行します。OPTFINALLYを省略した通常実行では、VAR書戻しエラーがCALL先の外へ伝わると原版の共有変数が0になる場合があります。UWSC#は失敗した式の代入先を保持します。

    静的CALLで事前登録したファイルを添字関数からEVAL("CALL ファイル名.uws")で呼び出す場合も、書戻し、エラーの伝わり方、停止時の後片付けは静的CALLと同じです。

    VAR配列の添字関数がスクリプトを静的CALLする場合と、事前登録したスクリプトを動的CALLする場合を比較しました。どちらも、呼出し先の範囲外エラーが未処理のまま添字関数を抜けると、添字0へ書き戻しました。添字関数内でエラーを捕捉した場合は、関数が返した添字へ書き戻します。呼出し先の減算で数値変換に失敗した比較でも、未処理なら添字0、添字関数が捕捉した場合はその関数が返した添字へ書き戻しました。CALLが正常に戻り、その後に添字の数値変換に失敗した場合は、その配列への書戻しを打ち切ります。UWSC#は未処理の書戻しエラーのうち、最初の1件を通知します。

    UWSC#では、静的CALLで事前登録していないファイルも、添字関数からEVAL("CALL ファイル名.uws")で取り込めます。比較したコマンドライン版とUWSC# アプリでは、通常実行、子スレッドの停止、メイン終了の書戻しは、事前登録した場合と同じでした。空白や日本語を含むファイル名を式で組み立てる場合も同じです。たとえばEVAL("CALL <#DBL>bridge <#DBL>+<#DBL>日本語.uws<#DBL>")はbridge 日本語.uwsを取り込みます。原版UWSC Free 5.3.0.2では、未登録ファイルは取り込まれず、動的CALLのエラーは添字関数内または外側のEXCEPTで捕捉されました。子スレッドの停止要求やメイン終了がDLLの復帰より先に進んだ比較では、原版とコマンドライン版とUWSC# アプリはいずれもDLLが戻るまで待ち、未登録ファイルの取込みには進みませんでした。DLL復帰後、添字関数に入ってから動的CALLの直前で停止した比較でも、取込みには進みませんでした。OPTFINALLYを指定した条件では、3環境とも添字関数が停止前に設定した添字1を使って書き戻し、添字関数と子スレッドのFINALLYを実行しました。

    スクリプトファイルを引数にしてコマンドライン版とUWSC# アプリを起動した場合は、通常終了とEXITEXITでも、この後片付けを待ってからプロセスを終了します。

    ファイル引数で起動した実行では、コマンドライン版のCtrl+C・Ctrl+BreakやUWSC# アプリの停止・閉じる要求でも、DLL呼出しの復帰と後片付けを待って終了します。

    編集画面から再生したときは、通常終了やEXITEXIT、停止要求の後も画面が残り、後片付け後に編集・再生できます。再生中の閉じる要求は停止を要求します。DLL呼出しと後片付けが終わってから、もう一度閉じてください。

    WITHでmodule・objectを省略する

    WITH Sample
    PRINT .value
    .value=3
ENDWITH
MODULE Sample
    PUBLIC value=2
ENDMODULE

    WITHの対象を1回評価して保持し、本文では先頭ドットで変数・メソッドを参照します。module/classとCOM objectに利用でき、入れ子では内側の対象を使用します。外側のWITHが例外・取消・break/returnで終了しても対象を復元します。数値・文字列・EMPTY・NULL・NOTHINGは対象にできません。

    モジュールの省略した変数はVAR引数やTOKENの書戻しにも利用できます。COMの全provider・型・VAR形態の互換を確認したものではありません。WITH外の先頭ドットはエラーです。
