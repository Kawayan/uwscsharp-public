    UWSC# ヘルプ / スクリプトを予約実行する

    スクリプトを予約実行する

    UWSC# アプリでスクリプトを指定した時刻に実行し、結果を確認できます。最初はPRINTだけの短い.uwsファイルで試してください。

    一回だけ実行する

    1. UWSC# アプリを引数なしで起動し、「予約設定」から「登録・再予約を編集…」を開きます。
    2. 「予約監視を有効にする」をオンにします。空いている枠を選び、「登録・編集…」を押します。
    3. 表示名と実行する.uwsファイルを指定します。「この予約を有効にする」をオンにし、実行方式は「同一プロセス」、条件は「一回」を選びます。
    4. 日付と時刻を入力します。設定を保存する時点で現在の分より後になるよう、数分先を指定してください。「反映」を押し、登録画面で「設定を保存」を押します。
    5. 監視が停止中なら、本体の「予約監視を開始」を押します。指定した時刻まで本体を起動したままにしてください。
    6. 実行時刻を過ぎたら、「予約設定」から「実行履歴…」を開き、登録した行を選んで結果を確認します。実行結果が見つからない場合は「最新へ再読込み」を押し、本体の監視状態も確認してください。

    実行履歴を確認する

    「予約設定」の「実行履歴」から、保存済みの履歴を読み取り専用で表示できます。本体の監視操作を続けられる別画面で開きます。受付UTCと発生識別子の降順で50件ずつ表示し、「次のページ」「前のページ」で移動します。「最新へ再読込み」で先頭から読み直します。一覧で省略した長い題名も、選択した詳細では全文を表示します。受付時の対象・順序付き引数・方式と、開始・結果受取・終了確認・回収状態・診断を確認できます。引数は引用符付きで、改行などはエスケープ表示します。

    捕捉先が保存されている履歴では、HWND値・PID・TIDと窓の観測日時を詳細で確認できます。いずれも保存時の数値で、現在も同じ窓が有効とは限りません。旧履歴など捕捉先の記録がない場合は「未記録」と表示します。以前の履歴は読み込むだけでは書き換えません。

    履歴は保存された観測です。未完了の記録が現在も実行中とは限りません。結果未記録・終了未確認・回収未確認を分けて表示します。読込みに失敗した場合は直前の一覧を保持してエラーを通知します。履歴の選択や再読込みでは、実行結果や一回予約の消費状態を変更しません。

    予約の履歴は受付時の題名・パス・順序付き引数と、親が確認した開始・結果受取・終了の時刻、結果と資源回収の状態をJSONへ保存します。終了と回収を確認できた履歴は100件まで保持し、実行中・未回収の履歴は追加で保護します。履歴の保存失敗は実行結果と分けて通知します。スケジュール機能全体の完成や原版互換の確認には至っていません。

    履歴保存に失敗すると、以前に保存できた状態が一覧に残る場合があります。実行結果と履歴保存の診断を分けて確認してください。

    古い履歴の整理に失敗すると、回収済みの履歴が上限を超えて残る場合があります。新しい履歴の保存後に整理が失敗する場合もあるため、保存診断と実際の履歴を併せて確認してください。

    本体終了時の履歴保存は5秒まで待ちます。履歴保存の期限切れは実行資源の未回収とは分けて扱います。実行資源の回収が済んでいれば、履歴保存が完了しなくても終了できます。保存できなかった履歴は再起動後の一覧に残らない場合があります。

    予約設定を編集する

    予約設定のJSONがまだない場合だけ、%APPDATA%/UWSC/UWSC.INIの[SCHEDULE] MaxNumberを初期枠数に使います。未指定・不正値は40枠、範囲外の整数は40〜400枠へ補正します。既存JSONがある場合はJSONの枠数を優先し、INIを変更しても保存済みの予約や枠数は変わりません。予約画面での保存先はJSONであり、INIへは書き戻しません。破損JSONはINIで自動置換せず、既存の退避・復旧手順を使います。

    「予約設定」から「登録・再予約を編集」を開くと、40〜400枠の登録を編集できます。表示名・.uwsのパス・実行方式・条件・順序付き引数を設定し、コピー・移動・削除を原稿へ反映します。空欄の引数を追加すると空文字列を渡します。変更は「設定を保存」で確定し、取消ではファイルを変更しません。一回の新規登録・日時変更・明示再予約は、保存時点で現在の分より後の日時が必要です。移動や表示名・パス・引数だけの編集では消費を解除しません。

    編集中に同じ本体の実行状態や別の保存で設定が更新された場合も、保存競合として上書きを拒否し、編集原稿を保持します。再読込みするには編集を取り消してから「設定を再読込み」を選んでください。停止中の監視は設定保存だけでは開始しません。「予約監視を開始」で明示的に開始します。読込み失敗時は元のファイルを保持し、「退避して初期化」は利用者が確認した場合だけ行います。

    「予約の実行開始時にビープを鳴らす」を有効にすると、実際の開始を確認した実行ごとに1回、OSの標準通知音を依頼します。初期値は無効です。待機中や開始できなかった実行では鳴らしません。設定は実行先への引渡し時に固定するため、既に引き渡した実行は後から変更しても切り替わりません。通知の失敗は診断を表示し、スクリプトの実行は続けます。音量・出力先・OSのサウンド設定により聞こえない場合があります。

    「時刻条件に合わせて休止から復帰する」を有効にすると、監視中の本体が時刻条件のための自動復帰を依頼します。初期値は無効です。通常は候補の1分前、直前に設定した場合などは候補の時刻に依頼します。本体を起動したままにする必要があり、終了すると復帰要求を解除します。シャットダウンしたPCを起動する機能ではありません。OS・機器・電源設定と復帰にかかる時間によって、指定した分に間に合わない場合があります。過ぎた分を後からまとめて実行しません。

    数値式などは未来の全てを一度に調べず、探索を続けるためだけに復帰する場合もあります。起動時や窓条件だけでは未来の復帰時刻を作りません。未対応などの診断が出ても通常の時刻条件の監視と実行は続けます。設定変更を読み取ったとき、監視を停止したとき、本体を終了するときに、それまでの復帰要求を取り消します。

    予約に連動した実音と、実機での休止・復帰は未確認です。

    登録画面には、ウィンドウ条件・ビープ・休止復帰の実行接続を「未実装」とする旧案内が残っています。利用できる設定と未確認の条件は、このページの説明を参照してください。

    ウィンドウを条件にする

    ウィンドウ条件は、タイトルの部分一致とクラス名の完全一致で判定します。英字の大文字と小文字を区別せず、両方を指定した場合は両方への一致が必要です。非表示・最小化したトップレベル窓も対象です。監視中は約500msごとに観測しますが、前の観測が終わるまで次を重ねません。取得に失敗した観測では新しく受け付けず、消失の履歴も変更しません。

    一致した窓は、行ごとに一度受け付けます。一致しなくなった窓や消失した窓は、再び一致すれば受付対象になります。同じ行の実行中は同時実行せず、待機は1件までです。GETID(GET_SCHEDULE_WIN)は実行ごとに捕捉した窓を返し、所有者が変わった窓や取得できない窓では-1を返します。監視を再開すると、その時点で一致する窓を新しい候補として扱います。観測の間に同じ窓番号・所有者で再生成された場合は区別できません。

    予約監視と本体の終了

    引数なしで本体を起動すると、有効な予約設定がある場合に監視の開始を試みます。設定を読み込めない場合や、別の本体が監視中の場合は、新しい予約を実行しません。画面の監視状態を確認してください。別の本体が終了しても自動では引き継がず、「予約監視を開始」で明示的に取得を試みます。コマンドライン版の起動や、ファイルの関連付けからの起動では、予約監視を開始しません。

    監視の所有権を失った本体は新規受付を止め、実行中の予約へ取消を要求します。その後の一回予約の結果を予約設定へ書き戻しません。別の本体が監視を取得したとき、予約設定で結果が確定していない消費済みの一回予約は「結果不明」として保持し、自動では再実行しません。

    予約用プロセスの接続確認に失敗した場合、開始を確認できなくても、結果や資源回収を確認済みとは扱いません。履歴の結果・開始情報・資源回収と診断を確認してください。消費済みの一回予約は自動では再実行しません。

    予約用プロセスとの通信が内部の10秒期限を超えると、期限切れのエラーを返します。送信では、順番待ちと書込みを合計した期限です。呼出し元からの取消要求とは区別します。通知を待つ先頭1バイトの受信前には、この通信期限を開始しません。送信中に失敗した通信路では、後続の通知も送信しません。結果だけで回収済みと判断せず、資源回収と診断も確認してください。

    キー送信後に親のホットキーを復元できない場合、キーの押下・解放を受け取れても資源回収済みとは扱いません。履歴と診断を確認してください。未回収の実行が残る間は新しい実行と終了を保留します。

    本体を閉じると新規受付を止め、予約へ取消を要求して回収を待ちます。回収を確認できない場合は、まず終了を保留します。もう一度閉じると、回収未確認のまま終了するかを確認します。「いいえ」は画面を残し、「はい」は通常の未保存確認へ進みます。回収の確認と原稿の破棄は別の判断です。未保存確認で終了を取り消した後も、予約の監視は停止したままです。再開する場合は「予約監視を開始」を押してください。同じ本体の起動時予約は繰り返しません。

    復帰時刻の計算などの終了処理が残る場合も、本体の終了を保留します。処理が終わった後にもう一度閉じると、通常の終了を試みます。

    予約実行のログを確認する

    予約の既定ログは、改行込みのUTF-8で1実行4MiBまで保持し、古い出力から省略します。1秒周期と終了時に保存し、省略したバイト数と保存失敗は実行診断へ残します。全体64MiBの範囲で、終了と資源回収を確認できた古い管理ログを整理します。実行中・未回収・所有不明のログや既存のGUID名ログは削除しません。保護するファイルで容量を使い切った場合は新たな既定ログ保存を省略し、スクリプトを続けます。置換用の一時ファイル分も空き容量が必要です。

    ログを保存できなくても、スクリプト自体の成功・失敗・取消完了は別に扱います。履歴に残る結果とログ保存の診断を併せて確認してください。

    予約の管理領域をOPTION LOGPATHで明示すると、TRYで扱えるエラーとして設定変更を拒否します。自身の既定ログと同じパスも対象です。空のパスで既定へ戻す操作は利用できます。管理領域外に明示した保存先は全体容量の整理対象から外し、通常のログ設定に従います。周期・終了時の保存失敗と容量不足の省略は、スクリプトの終了コードと分けて通知します。
