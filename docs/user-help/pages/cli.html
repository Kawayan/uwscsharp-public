    コマンドライン版の使い方と起動引数

    コマンドラインから実行する

    コマンドライン版のプレビューのサポート範囲は、通常の.uwsの実行、引数の受け渡し、標準出力・標準エラー、終了コード、ローカルのファイル処理、取消と再実行です。Windowsの画面・入力操作やCOMなどは、各機能の説明に記載した対応状況を確認してください。

    ソースから実行する場合は、リポジトリのルートで次の形式を使います。

    dotnet run --project src/UWSCSharp.Cli -- examples/parameters.uws "日本語" "a b"

    ランタイム依存のコマンドライン版配布物では.NET 10 Runtimeが必要です。展開先で次の形式を使います。

    dotnet UWSCSharp.Cli.dll script.uws "日本語" "a b"

    原版UWSCやUWSC#で作成したUWS05形式の.uwsファイルは、通常のスクリプトと同じ指定で実行でき、CALLの呼出し先にも使えます。ファイル形式が不正な場合や、検査値が本文と一致しない場合は、読込み時にエラーを表示します。

    スクリプトをUWS05へ変換する

    /Aを先頭に指定します。出力先を指定した場合は元ファイルを保ち、指定したファイルにUWS05を生成します。出力先を省略した場合は、変換前のバイト列を同じフォルダーの.orgへ保存してから、元のパスをUWS05に置き換えます。

    dotnet UWSCSharp.Cli.dll /A source.uws converted.uws
dotnet UWSCSharp.Cli.dll /A source.uws

    入力はUTF-8（BOMの有無を問わず）、CP932、BOM付きUTF-16LE、BOM付きUTF-16BEに対応します。空行・コメント・字下げを保持し、改行はCRLFにそろえます。出力先、または省略時の.orgが既にある場合はエラーになり、入力と既存ファイルを保持します。原版UWSC 5.3.0.2は、この2条件で既存ファイルを上書きします。.orgの保存後に元のパスの置換が失敗した場合は、.orgを保持します。書込みと削除を禁止するロックを入力にかけた試験では、置換が失敗して入力と.orgの両方に元の内容が残りました。

    読み取り専用の入力を出力先の指定なしで変換すると、入力と.orgに元の内容が残り、終了コード1を返します。

    出力先や退避先に一時ファイルを作成できない場合や、作成したファイルを移動できない場合は、診断に保存先のパスが表示されます。

    BOM付きUTF-16LEまたはUTF-16BEの入力を読み取れない場合は、入力パスを含む診断を表示して終了コード1を返します。入力はそのまま残り、出力や.orgは作成されません。

    置換に失敗して.orgが残った場合は、まだ存在しない別の出力先を指定して変換をやり直せます。入力と.orgはそのまま残ります。

    変換が途中で中断されると、.uwsc-scramble-*.tmp が残ることがあります。変換プロセスが終了したことと、入力や.orgに必要な内容が残っていることを確認してから、一時ファイルを削除してください。

    変換後に本文を復元できることを確認してから保存します。置換記号との衝突を回避できない場合は、入力を保持してエラーを返します。

    PARAM_STRの規則

    コマンドライン版専用の先頭オプションを除いた最初の引数は、スクリプトのパスです。それ以降だけがPARAM_STRへ入り、スクリプト名や実行ファイル名は入りません。配列は0始まりです。順序、空文字、Unicode、空白、数値に見える文字列も文字列として保持します。シェルが事前に除去・変換した引用符などは復元しません。

    終了後の入力フック回収（Windowsのコマンドライン版）

    選択的な入力禁止フックが終了時に残った場合に、同じコマンドライン版で回収を試すための指定です。LOCKHARDEXはコマンドライン版とUWSC# アプリで使用できます。公開経路の機能全体の受入は一部対応です。

    dotnet UWSCSharp.Cli.dll --input-cleanup=manual script.uws "日本語"

    このオプションはスクリプトのパスより前の先頭に指定します。パスより後の文字列は、同じ表記でもPARAM_STRへ渡します。先頭の--input-cleanup=はコマンドライン版設定として予約されるため、同じ名前のファイルには./または絶対パスを付けてください。

    標準入力と標準エラーを端末へ接続して使います。標準出力のリダイレクトは可能です。端末条件を満たさない場合、不明な値を指定した場合、Windows以外で指定した場合は、スクリプト実行前に終了コード2で拒否します。

    未回収所有者が残ったときだけ、終了前に操作を待ちます。未回収がなければ待ちません。指定しない通常起動でも操作待ちは追加せず、未回収の診断を出して終了します。

    • retryとEnter：明示的に1回再回収し、診断と未回収所有者数を表示します。残る場合だけ再び操作を待ちます。
    • exitとEnter：未回収が残ることを表示して終了します。既存の非ゼロ終了コードを維持し、元のコードが0なら1にします。
    • Ctrl+C：操作待機から退出して130を返します。回収要求中は退出要求を保持し、その要求の協調待機が終わってから退出します。

    コマンドの大文字小文字と前後の空白は無視します。入力は64文字までで、超過した行や未知のコマンドでは再回収しません。受付前や前の回収中に届いた残留入力は、新たな要求として扱いません。

    再回収後も過去の診断が残る場合があります。未回収所有者数が0なら回収完了ですが、元の実行エラーや取消の終了コードを0へ変更しません。プロセス終了と明示解除の成功も区別してください。OSや所有スレッドの応答停止を強制回復する操作ではありません。

    手動回収とCtrl+C/Breakによる取消は、Windows 11 x64の検証用コンソールで確認しています。Windows Terminalなどの追加端末、物理キーボード操作、実OSのフック解除障害は未確認です。端末が異なる場合の入力配送や、OS障害からの回復を一般保証するものではありません。

    スクリプトを再実行する（Windowsのコマンドライン版）

    POFF(P_UWSC_REEXEC, TRUE) は、現在のスクリプトを終了し、同じファイルと引数で別のコマンドライン版プロセスを起動します。元の作業ディレクトリと --input-cleanup=manual の指定も引き継ぎます。

    再実行が必要な場合だけこの行へ進むように条件を付けてください。起動するたびにこの行を実行すると、再実行を繰り返します。

    元のコマンドライン版は、後片付けが成功して新しいプロセスを起動できた場合に終了コード0を返します。再実行したスクリプトの終了コードは、新しいプロセスが返します。後片付けに失敗した場合は新しいプロセスを起動しません。

    Windowsのコマンドライン版で再実行を指定する場合は、第2引数に TRUE を指定してください。UWSC# アプリの指定はスクリプトからUWSC# アプリを再起動するを参照してください。

    Windowsの電源と画面を操作する

    Windowsのコマンドライン版とUWSC# アプリでは、POFF(コマンド) でWindowsに電源や画面の操作を要求できます。UWSC# アプリの予約実行でも、同じプロセスと別プロセスの両方から要求できます。

    コマンド要求する操作
    P_POWEROFF電源を切る
    P_LOGOFFログオフする
    P_REBOOTWindowsを再起動する
    P_SUSPEND休止する
    P_SUSPEND2スタンバイに入る
    P_MONIPOWERモニターを省電力状態にする
    P_MONIPOWER2モニターの電源を切る
    P_MONIPOWER3モニターの電源を入れる
    P_SCREENSAVEスクリーンセーバーを起動する

    P_FORCE は電源断、ログオフ、Windowsの再起動にだけ OR で追加できます。アプリを強制終了するため、未保存の内容が失われることがあります。第2引数は、UWSC#を再起動する P_UWSC_REEXEC 専用です。

    操作の呼び出しが成功すると EMPTY を返します。Windowsが要求を受理した後の状態は、電源設定、権限、機器やセッションによって決まります。APIがエラーを返した場合は EXCEPT で捕捉できます。予約実行で P_UWSC_REEXEC を指定すると、捕捉できるエラーになります。

    終了コードと停止

    コード意味
    0正常終了
    1失敗
    2スクリプト引数なし、手動回収の起動設定エラー、/Aの引数の個数が不正
    130協調取消

    スクリプトがEXITEXITに終了コードを指定すると、後処理が成功した場合はその値を返します。1・2・130も明示指定できるため、コードだけではコマンドライン版自身のエラーと区別できません。診断はstderrも確認してください。終了コードの省略、通常の最終行到達、メインのEXITは0です。

    stdoutとstderrはUTF-8です。Ctrl+Cの配送は端末に依存します。取消・実行エラー時も、保留中の出力は終了時に保存される場合があります。ロールバックは行いません。

    PRINTのログ保存

    コマンドライン版はPRINTの内容を、主スクリプトと同じフォルダーのUWSC.LOGへ保存します。既定では分単位の日時を付け、直近2,000件を保持します。実行中は約1秒ごとに保存を試み、正常終了・エラー・取消の後にも最終保存します。保存先に書込み権限がない場合は診断を確認してください。

    保存不要の場合はOPTION LOGFILE=1を先頭に指定してください。保存形式や保存先の変更はログOPTIONを参照してください。周期保存が失敗するとstderrへ通知して再試行します。回復後に最終保存が成功した場合、周期保存の失敗だけで終了コードを変更しません。最終保存だけが失敗すると終了コード1となり、実行エラーや取消と重なった場合は元の診断に終了処理の失敗を付記します。
